## 详细覆盖情况

### ✅ Case 1: 当前 Web Agent Crash

**测试：** `TestP5_Case1_WebAgentCrash`  
**位置：** `internal/agent/p5_accept_test.go:63`

**验证内容：**
- ✅ Agent A 崩溃后，其管理的进程（sleep）继续运行
- ✅ 用户可访问 Agent B 的 Web UI
- ✅ Agent B 可响应 API 请求（ListNodes, Overview）
- ✅ Agent B 不会接管 A 的进程

**状态：** 完全覆盖

---

### ❌ Case 2: Agent A 与 Agent B 网络断开

**预期：**
- 两边本地 Process 正常
- 远程管理失败
- 不发生 Process 迁移

**现状：** 无对应测试

**建议：**
创建测试模拟网络分区（通过阻止 gossip/RPC 端口访问），验证：
1. 本地 Process 继续运行
2. 跨节点 RPC 返回 timeout/unreachable 错误
3. Gossip 将对方标记为 STALE/UNKNOWN
4. 不触发进程迁移（V1.0 本就不支持）

**优先级：** Medium（生产环境常见场景）

### ❌ Case 6: Restart RPC 已执行但 Response 丢失

**预期：**
- 重试相同 operation_id
- 不重复 Restart

**现状：** 无对应测试

**背景：**
- 代码中 `operation_id` 已在 mutation API 中强制要求
- FSM 和 Process Manager 都使用 `operation_id` 去重

**建议：**
创建测试验证：
1. 第一次调用 Restart(operation_id="op-1") 成功，进程重启
2. 第二次调用 Restart(operation_id="op-1") 返回成功但不再重启进程
3. 验证进程只重启了一次

**优先级：** High（幂等性是分布式系统的基本保证）

---
